# RAG 元认知系统探索

## 背景

主智能体需要"认识自己"——了解项目架构、设计文档、API 等信息，以便向用户介绍项目。

**当前方案**：`getProjectIntro` 工具读取单个 md 文件
**问题**：项目有 56 个文档（~400KB），无法全部塞入 prompt

**目标**：用 RAG 实现智能文档检索，让 AI 能根据问题找到相关文档

---

## 话题 1：RAG 是否必要？

**讨论**：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 目录导航 | 简单、无依赖 | 需要 2 次调用，依赖目录结构 |
| RAG | 语义检索、一步到位 | 需要向量化、复杂度高 |

**结论**：
- [x] 采用 RAG 方案
- 理由：面试项目需要炫技，RAG 能展示向量检索能力
- 数据现成：56 个文档，不需要额外构建

---

## 话题 2：技术选型

### 2.1 向量存储

| 方案 | 优点 | 缺点 |
|------|------|------|
| 外部数据库（Milvus/Pinecone） | 生产级、可扩展 | 部署复杂 |
| **内存存储（LangChain4j）** | 简单、无依赖 | 重启丢失（可接受） |

**结论**：使用 `InMemoryEmbeddingStore`，启动时加载文档

### 2.2 Embedding 模型

| 方案 | 优点 | 缺点 |
|------|------|------|
| OpenAI text-embedding-3-small | 效果好 | 需要 API 调用、有成本 |
| **本地模型（all-MiniLM-L6-v2）** | 离线可用、无成本 | 效果略差（可接受） |

**结论**：使用本地模型 `all-MiniLM-L6-v2-q`（量化版本）
- 依赖：`langchain4j-embeddings-all-minilm-l6-v2-q:1.9.1-beta17`
- 大小：~30MB（量化后更小）
- 内存：~100MB
- 无需 GPU，CPU 即可运行
- 无需 API Key
