# 记忆系统探索

## 背景

项目已部署上线：https://vibe.fzhiyu2333.top/

当前 AI Agent 没有记忆能力，每次对话都是全新开始。需要探索在浏览器端实现简单的记忆系统，让 AI 能够记住用户的偏好和历史交互。

## 待讨论话题

### 话题 1：记忆存储方案

**问题**：记忆数据存储在哪里？

**可能的方案**：
- [x] localStorage（简单，持久化，但有容量限制 ~5MB）✅ 选定
- [ ] IndexedDB（容量大，支持复杂查询）
- [ ] 后端数据库（需要用户登录，复杂度高）

**讨论结论**：
选择 **localStorage**，理由：
1. 记忆数据量预估 < 1MB，容量足够
2. 面试演示项目，简单 > 复杂，不需要跨设备同步
3. RAG 已展示高级技术，记忆系统重点在设计思路
4. 封装 `MemoryStore` 类，方便后续替换存储后端

---

### 话题 2：记忆内容设计

**问题**：AI 应该记住什么？

**可能的内容**：
- [x] 用户偏好（喜欢的音乐风格、灯光颜色、香氛类型）✅
- [x] 历史场景（用户创建过的场景）✅
- [x] 对话摘要（重要的对话内容）✅
- [ ] 反馈记录（用户对 AI 编排的反馈）❌ 无点赞点踩机制

**讨论结论**：
1. 采用 **Markdown 文档**（MEMORY.md）存储记忆，而非结构化 JSON
2. 理由：AI 友好、人类可读、展示效果好（"AI 写日记"）
3. 记忆内容包括：用户偏好、历史场景、重要对话
4. 修改方式：借鉴 Claude Code 的**字符串匹配替换**机制

---

### 话题 3：记忆注入方式

**问题**：如何将记忆注入到 AI 对话中？

**可能的方案**：
- [x] System Prompt 注入（每次对话带上记忆摘要）✅ 选定
- [ ] 工具调用（AI 主动调用工具查询记忆）
- [ ] 混合方式（关键记忆注入 + 详细记忆按需查询）

**讨论结论**：
选择 **System Prompt 注入**，每次对话时将 MEMORY.md 内容注入到 Prompt 中。
需要配合容量管理（话题5）限制记忆长度。

---

### 话题 4：记忆更新机制

**问题**：何时更新记忆？如何更新？

**可能的方案**：
- [ ] 实时更新（每次交互后立即更新）
- [ ] 会话结束时更新（对话结束时总结并存储）
- [x] AI 主动更新（AI 判断重要信息时调用工具存储）✅ 选定

**讨论结论**：
采用**工具为主，总结异步**的方案：

1. **SaveMemory 工具**（同步）：AI 发现重要信息时调用，写入「最近」区
2. **异步总结任务**：检测到记忆超长时，后台触发总结

```
对话中 AI 判断有价值 → SaveMemory 工具 → 写入「最近」区
                                            ↓
                                    检测超长 → 异步总结
```

---

### 话题 5：记忆容量管理

**问题**：记忆过多时如何处理？

**可能的方案**：
- [ ] FIFO（先进先出，删除最旧的记忆）
- [ ] 重要性排序（保留重要记忆，删除次要记忆）
- [x] 摘要压缩（将多条记忆压缩成摘要）✅ 选定

**讨论结论**：
采用**分区存储 + 异步总结**，借鉴人脑记忆巩固机制：

```markdown
# 记忆

## 摘要（总结后的长期记忆）
用户喜欢爵士乐和暖色灯光...

## 最近（新增的短期记忆）
- 2025-12-29: 用户说不喜欢太亮的灯
```

**工作流程**：
| 人类 | AI 记忆系统 |
|------|-------------|
| 白天经历事情 | 对话中写入「最近」区 |
| 睡觉时整理记忆 | 异步总结，合并到「摘要」区 |
| 醒来记忆已巩固 | 下次对话用整理好的记忆 |

**触发条件**：记忆文件 > 2000 字符时触发总结

---

### 话题 6：遗忘机制

**问题**：是否允许智能体忘记某事？

**讨论结论**：
采用**追加抵消**机制，而非主动删除：

```
用户: "我不喜欢紫色"  → 记录: 用户不喜欢紫色
用户: "忘掉刚才说的" → 记录: 用户说忘掉"不喜欢紫色"
                            ↓
                    总结时两条抵消 → nothing
```

**设计理念**：
- 更像人脑：不是"删除"记忆，而是"覆盖/更新"认知
- 只追加不删除，实现简单
- 有完整记录，可追溯
- 总结智能体自动处理矛盾
