# 探索文档：环境变化检测系统

## 探索目标

设计一个检测系统，监测行驶过程中的环境变化，触发氛围调整。

## 背景

"上海→杭州"行驶模拟需要模拟复杂场景变化，系统需要检测这些变化并触发相应的氛围调整。

## 待检测的变化类型

| 类型 | 触发条件 | 优先级 |
|------|----------|--------|
| 城市变动 | 从上海进入杭州 | 中 |
| 时间段变动 | 如从下午进入傍晚 | 中 |
| 车速变动 | 速度变化超过阈值 | 低 |
| 天气变动 | 天气类型改变 | 高 |
| 心率异常 | 大幅变动且持续10s | 高 |
| 压力异常 | 大幅度变动 | 高 |
| 疲劳异常 | 大幅度变动 | 高 |

## 探索记录

### 话题1：检测系统架构

**问题**：检测系统应该放在前端还是后端？

**方案对比**：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 前端检测 | 实时性好、无网络延迟 | 逻辑分散、难以复用 |
| 后端检测 | 集中管理、可复用 | 需要频繁同步环境数据 |
| 混合方案 | 前端检测+后端决策 | 复杂度高 |

**结论**：采用 **前端检测** 方案

**理由**：
- 环境数据本来就在前端（vibeStore）
- 不需要额外的后端同步
- MapPanel 已经在更新 environment

**实现思路**：
```
vibeStore.environment 变化
    ↓
useEnvironmentDetector (新 composable)
    ↓
检测到显著变化
    ↓
调用 store.analyze() 触发 Agent
```

### 话题2：变化检测阈值

**问题**：各类变化的检测阈值如何设定？

#### 2.1 车速变动

```
触发条件：速度变化 > 30 km/h 且持续 5s
示例：从 120 km/h 降到 60 km/h（可能进入服务区）
```

#### 2.2 心率异常

```
触发条件：心率变化 > 20 bpm 且持续 10s
示例：从 70 bpm 升到 95 bpm（可能紧张/激动）
```

#### 2.3 压力/疲劳异常

```
触发条件：数值变化 > 0.3 且持续 10s
示例：压力从 0.3 升到 0.7（需要舒缓）
```

#### 2.4 城市变动

```
触发条件：location.cityName 改变
示例：从"上海"变为"杭州"
```

#### 2.5 时间段变动

```
触发条件：timeOfDay 改变
示例：从 AFTERNOON 变为 EVENING
```

#### 2.6 天气变动

```
触发条件：weather 改变
示例：从 SUNNY 变为 RAINY
```

### 话题3：检测系统实现方案

**检测器结构**：

```typescript
interface ChangeEvent {
  type: 'city' | 'time' | 'speed' | 'weather' | 'heartRate' | 'stress' | 'fatigue'
  oldValue: any
  newValue: any
  description: string  // 如"进入杭州"、"天气转雨"
}
```

**两类检测逻辑**：

| 类型 | 检测方式 | 示例 |
|------|----------|------|
| 即时变化 | 值改变即触发 | 城市、时间段、天气 |
| 持续变化 | 超阈值且持续N秒 | 心率、压力、疲劳、车速 |

**变化合并策略**：

**结论**：多个变化**合并后**再触发 Agent

**合并窗口**：检测到第一个变化后，等待 3-5 秒收集其他变化，然后一次性触发

```
变化1: 进入杭州
    ↓ (等待 3s)
变化2: 天气转雨
    ↓ (窗口结束)
合并触发 Agent: "进入杭州 + 天气转雨"
```

### 话题4：与 Agent 的集成

**问题**：检测到变化后如何触发 Agent 调整氛围？

**结论**：直接发给**氛围 Agent**

**理由**：
- 环境变化主要影响氛围（灯光、音乐、香氛）
- 不需要经过主 Agent 中转
- 响应更快

**触发方式**：
```typescript
// 检测到变化后，构造消息发给氛围 Agent
const changes = ["进入杭州", "天气转雨"]
const message = `环境变化：${changes.join('，')}，请调整氛围`

// 直接调用氛围 Agent
vibeApi.callAmbienceAgent(sessionId, message, environment)
```

**待确认**：
- 是否需要新增后端接口？
- 还是复用现有的某个接口？

**调研结果**：

现有架构：`前端 → analyze → MasterAgent → CallVibeAgentTool → VibeAgent`

直接调用氛围 Agent 需要**新增 API**：

```java
// 新增 Controller 端点
@PostMapping("/vibe/trigger")
public void triggerVibeAgent(@RequestBody TriggerRequest req) {
    vibeTaskManager.startTask(req.sessionId, req.environment);
}
```

**结论**：需要新增 `/vibe/trigger` 接口
