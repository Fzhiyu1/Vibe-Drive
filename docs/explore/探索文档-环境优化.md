# 探索文档：环境优化

## 探索目标

研究如何优化 Vibe Drive 的环境感知和利用，包括：
- 环境数据的充分利用
- 环境数据的扩展
- 环境变化感知
- 环境与氛围的智能联动

## 背景

当前 Vibe Drive 的环境数据结构已经比较完善，但存在以下问题：
1. AI 未充分利用环境细节数据
2. 环境数据是静态的，缺少变化感知
3. 环境与氛围是单向关系，缺少反馈机制

### 话题1：环境细节数据的充分利用

**讨论日期**：2025-12-28

#### 1.1 问题分析

**现象**：AI 生成的氛围方案缺乏个性化，不同城市、不同道路的推荐结果相似。

**根因**：
1. System Prompt 虽然提到了细节字段，但缺少具体使用示例
2. AI 不知道如何将城市/道路信息转化为氛围选择
3. 缺少城市特色、道路氛围的知识库

#### 1.2 解决方案

**方案A：增强 System Prompt 示例**

在 `vibe-system.txt` 中添加具体的使用示例：

```
### 城市特色利用示例
- 上海 → 可选《夜上海》《外滩十八号》等城市主题歌曲
- 成都 → 可选《成都》《蓉城》等
- 北京 → 可选《北京北京》《故乡的云》等
- 杭州 → 可选《梦里水乡》《西湖》等

### 道路氛围利用示例
- 滨海大道 → 海洋主题氛围，蓝色灯光
- 山间公路 → 自然主题，绿色灯光
- 城市快速路 → 都市主题，现代感音乐
```

**方案B：创建城市/道路知识库**

创建结构化的知识库，供 AI 查询：

```json
{
  "cities": {
    "上海": {
      "songs": ["夜上海", "外滩十八号"],
      "lightColor": "#FFD700",
      "scent": "CITRUS"
    }
  }
}
```

**方案C：让 AI 自由发挥**

不提供固定映射，而是指导 AI 如何思考：

```
当看到城市名时，思考：
1. 这个城市有什么特色？（文化、气候、风格）
2. 有没有与这个城市相关的经典歌曲？
3. 这个城市给人什么感觉？（现代/古典/浪漫/活力）
```

#### 1.3 推荐方案

**推荐：方案C（指导思考）+ 方案A（少量示例）**

原因：
- 固定映射会限制 AI 的创造力
- 但完全没有示例，AI 可能不知道如何开始
- 少量示例 + 思考指导是最佳平衡

### 话题3：环境变化感知机制

**讨论日期**：2025-12-28

#### 3.1 当前问题

当前环境数据是静态的，每次分析都是独立的，不感知变化。

**场景示例**：
- 从晴天进入隧道 → 应该调暗灯光
- 从城市进入高速 → 应该切换氛围
- 天气突然变化 → 应该适应新天气

#### 3.2 变化检测设计

**方案A：前端检测 + 推送**

```typescript
// 前端监听环境变化
watch(environment, (newEnv, oldEnv) => {
  const changes = detectChanges(newEnv, oldEnv)
  if (changes.length > 0) {
    // 推送变化事件
    vibeApi.notifyEnvironmentChange(sessionId, changes)
  }
})
```

**方案B：后端定期比较**

```java
// 后端存储上次环境，定期比较
@Scheduled(fixedRate = 30000)
public void checkEnvironmentChanges() {
  Environment current = getCurrentEnvironment();
  Environment previous = getPreviousEnvironment();
  List<Change> changes = detectChanges(current, previous);
  if (!changes.isEmpty()) {
    triggerAmbienceUpdate(changes);
  }
}
```

**方案C：事件驱动**

定义环境变化事件类型：

```java
enum EnvironmentChangeType {
  WEATHER_CHANGED,      // 天气变化
  LOCATION_CHANGED,     // 位置类型变化（城市→高速）
  SPEED_ZONE_CHANGED,   // 速度区间变化（进入L2/L3）
  TIME_PERIOD_CHANGED,  // 时段变化（下午→傍晚）
  MOOD_CHANGED          // 情绪变化
}
```

#### 3.3 推荐方案

**推荐：方案C（事件驱动）**

原因：
- 不是所有变化都需要响应
- 事件驱动可以精确控制响应逻辑
- 避免频繁触发氛围更新

### 话题4：环境与氛围的智能联动

**讨论日期**：2025-12-28

#### 4.1 当前问题

当前是单向关系：环境 → 氛围

缺少：
- 氛围对环境的反馈
- 多元素之间的联动

#### 4.2 联动场景

| 场景 | 联动效果 |
|------|----------|
| 音乐节奏变化 | 灯光随节奏闪烁 |
| 进入隧道 | 灯光自动变亮 |
| 播放舒缓音乐 | 按摩切换到放松模式 |
| 用户跳过歌曲 | 调整后续推荐风格 |
| 疲劳值上升 | 自动切换提神氛围 |

#### 4.3 实现思路

**灯光随音乐节奏**：

```typescript
// 前端获取音频分析数据
const audioContext = new AudioContext()
const analyser = audioContext.createAnalyser()

// 根据节拍调整灯光
function updateLightWithBeat(frequencyData: Uint8Array) {
  const bass = getAverageFrequency(frequencyData, 0, 10)
  // 低音强时闪烁
  if (bass > threshold) {
    triggerLightPulse()
  }
}
```

**疲劳自动响应**：

```java
// 后端监听生理数据变化
if (biometrics.fatigueLevel > 0.7 && previousFatigue <= 0.7) {
  // 触发提神氛围
  vibeAgent.execute("用户疲劳值上升，请切换到提神氛围")
}
```
