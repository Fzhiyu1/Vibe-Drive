## Q: 智能体架构是怎样的？

### 双智能体设计

```
┌─────────────────┐         ┌─────────────────┐
│  Master Agent   │         │   Vibe Agent    │
│  (主智能体)     │ ──────→ │  (氛围智能体)   │
│                 │ ←────── │                 │
│ - 用户对话      │  委派   │ - 环境感知      │
│ - 记忆管理      │  结果   │ - 氛围编排      │
│ - 通用问答      │         │ - 工具调用      │
└─────────────────┘         └─────────────────┘
```

### 职责分工

**Master Agent（主智能体）**：
- 接收用户输入
- 判断意图（闲聊 vs 氛围请求）
- 管理用户记忆
- 简单请求直接处理
- 复杂氛围请求委派给 Vibe Agent

**Vibe Agent（氛围智能体）**：
- 接收环境数据
- 分析用户需求
- 规划氛围方案
- 调用工具执行

### 异步执行机制

**关键设计**：Vibe Agent 是异步执行的，不阻塞用户交互。

```
用户发消息 → Master Agent 立即回复 → 异步启动 Vibe Agent
                ↓                              ↓
           "好的，正在为您调整氛围"      后台编排（可能需要几秒）
                                              ↓
                                      SSE 推送执行结果
```

**为什么异步？**
- 氛围编排涉及多个工具调用（搜索音乐、设置灯光等），耗时较长
- 用户不需要等待编排完成才能继续对话
- 通过 SSE 实时推送进度，用户可以看到 Agent 的思考过程

### 通信方式

| 方向 | 方式 | 协议 |
|------|------|------|
| 用户 → Master Agent | 同步 | REST |
| Master Agent → Vibe Agent | 异步 | 内部调用 |
| Vibe Agent → 前端 | 流式推送 | SSE |

## Q: MAPE-K 闭环是什么？

Vibe Agent 内部采用 MAPE-K 自适应架构：

```
Monitor → Analyze → Plan → Execute
   ↑                         ↓
   └──────── 反馈 ───────────┘
```

| 阶段 | 职责 |
|------|------|
| Monitor | 接收环境 JSON，检测变化 |
| Analyze | LLM 语义理解，识别意图 |
| Plan | 规划氛围方案 |
| Execute | 调用工具，输出结果 |
| Knowledge | 提供上下文（用户偏好、历史） |

## Q: showPage 弹窗如何实现流式输出？

### 设计背景

用户请求查看详细内容时，AI 需要生成较长的文档。如果一次性生成完再显示，用户等待时间过长。

### 流式设计

采用 **showPage + appendPage** 两个工具配合：

1. `showPage(title, type)` - 打开空弹窗，返回 pageId
2. `appendPage(pageId, content)` - 多次调用，分段追加内容

### 调用流程

```
AI: showPage("项目介绍", "document")  → 返回 pageId "abc123"
AI: appendPage("abc123", "# 标题\n\n简介...")
AI: appendPage("abc123", "## 功能\n\n...")
AI: appendPage("abc123", "## 架构\n\n...")
```

### 前端处理

- showPage 在 tool_end 时打开弹窗（获取 pageId）
- appendPage 在 tool_start 时立即追加内容
- 用户可以实时看到内容逐步显示
